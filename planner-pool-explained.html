Clabernetes · direct runtime

Many devices.
Four planners.

Viele Geräte.
Vier Planner.

Every device needs its own build sheet. A small, shared pool writes those sheets, then hands the actual device startup to Kubernetes. The worker Pods stay; each planning process starts fresh.

Jedes Gerät braucht seinen eigenen Bauplan. Ein kleiner gemeinsamer Pool schreibt diese Pläne und übergibt den eigentlichen Gerätestart an Kubernetes. Die Worker-Pods bleiben, jeder Planungsprozess startet frisch.

01 · Planning

Why does a router need a plan?

Warum braucht ein Router einen Plan?

A kind and an image tell c9s what device you want. They do not yet describe all the work needed to run it as a Kubernetes Pod.

Kind und Image sagen c9s, welches Gerät du möchtest. Sie beschreiben aber noch nicht alle Schritte, um es als Kubernetes-Pod zu betreiben.

01

Ask the device expert

Den Geräte-Experten fragen

Containerlab knows the vendor-specific startup rules: commands, environment, files, mounts, interfaces and health checks. A planning process runs that knowledge against a recording runtime.

Containerlab kennt die herstellerspezifischen Startregeln: Befehle, Umgebung, Dateien, Mounts, Interfaces und Health-Checks. Ein Planungsprozess führt dieses Wissen gegen eine aufzeichnende Runtime aus.

02

Turn decisions into data

Entscheidungen werden Daten

The result is a device plan. The controller checks that its operations have supported Kubernetes equivalents, saves it, and renders the device Deployment. No NOS runs inside the planning worker.

Das Ergebnis ist ein Geräteplan. Der Controller prüft die unterstützte Kubernetes-Abbildung, speichert den Plan und erzeugt das Geräte-Deployment. Im Planungs-Worker läuft kein NOS.

03

Skip unchanged work

Unveränderte Arbeit überspringen

If the exact planning input already has a cached plan, c9s reuses it. A routine reconciliation does not need to run Containerlab again.

Existiert für die exakten Planungseingaben bereits ein gecachter Plan, nutzt c9s ihn erneut. Ein normaler Abgleich muss Containerlab nicht nochmals ausführen.

The same image does not mean the same plan. Two SR Linux Nodes can share image metadata while having different names, management addresses, links, certificates and generated files. Each Node still needs a plan for its own inputs.
Dasselbe Image bedeutet nicht denselben Plan. Zwei SR-Linux-Nodes können Image-Metadaten teilen, aber unterschiedliche Namen, Management-Adressen, Links, Zertifikate und erzeugte Dateien haben. Jeder Node braucht einen Plan für seine eigenen Eingaben.
02 · Request flow

One request, one fresh process.

Eine Anfrage, ein frischer Prozess.

The controller sends work to an available pool Pod in the manager namespace. When all workers are busy, pending work waits and retries. The same pool serves all lab namespaces.

Der Controller schickt Arbeit an einen verfügbaren Pool-Pod im Manager-Namespace. Sind alle Worker beschäftigt, wartet die Arbeit und wird erneut versucht. Derselbe Pool bedient alle Lab-Namespaces.

Worker lifetime

Reuse the Pod

Den Pod wiederverwenden

The pool avoids scheduling, starting and deleting a helper Pod for every planning request. A worker can plan r1, then a Linux tool, then a router from another lab.

Der Pool spart das Scheduling, Starten und Löschen eines Helfer-Pods für jede Planungsanfrage. Ein Worker kann erst r1 planen, dann ein Linux-Tool, dann einen Router aus einem anderen Lab.

Request lifetime

Reset the process

Den Prozess neu starten

Each request gets a new process and a private scratch directory. That keeps imported Go state and generated files from one request out of the next request. The pool does not cache a running Containerlab instance.

Jede Anfrage bekommt einen neuen Prozess und ein privates Scratch-Verzeichnis. Importierter Go-Zustand und erzeugte Dateien bleiben so auf ihre Anfrage begrenzt. Der Pool hält keine laufende Containerlab-Instanz im Cache.

03 · Reuse

The workers stay. The requests move on.

Die Worker bleiben. Die Anfragen wechseln.

Step through twelve planning requests. The same worker boxes take another Node each round; their process number changes. This is a simplified explanation of reuse, not a timing model.

Gehe zwölf Planungsanfragen durch. Dieselben Worker-Boxen übernehmen pro Runde einen weiteren Node; ihre Prozessnummer ändert sich. Das ist ein vereinfachtes Modell der Wiederverwendung, kein Zeitmodell.

A small pool at workEin kleiner Pool bei der Arbeit

Idle means available. When the queue is empty, the four worker Pods remain ready for the next new Node or plan change. Existing device Pods and their traffic do not need a worker to keep running.
Leerlauf bedeutet verfügbar. Ist keine Arbeit offen, bleiben die vier Worker-Pods für den nächsten neuen Node oder eine Planänderung bereit. Bestehende Geräte-Pods und ihr Traffic brauchen keinen Worker, um weiterzulaufen.
04 · Pod roles

Three helpers, three different jobs.

Drei Helfer, drei verschiedene Aufgaben.

The word “planner” also appears in device Pods. It is worth separating plan creation from applying the saved plan.

Das Wort „planner“ taucht auch in Geräte-Pods auf. Planerstellung und Anwendung des gespeicherten Plans sind getrennte Schritte.

Helper Where and how long Job
Shared pool worker Manager namespace · stays running Creates a plan in a fresh process, then accepts another request. Default: four Pods shared across labs.
planner init container Inside each device Pod · exits after preparation Reads the saved plan, checks its identity and prepares files and artifacts. It does not occupy a pool worker.
clabwire sidecar Inside each device Pod · stays running Prepares local networking, connects links and management, and reports connectivity readiness while the NOS runs.
Helfer Ort und Lebensdauer Aufgabe
Gemeinsamer Pool-Worker Manager-Namespace · bleibt aktiv Erstellt einen Plan in einem frischen Prozess und nimmt danach die nächste Anfrage an. Standard: vier Pods für alle Labs.
planner-Init-Container In jedem Geräte-Pod · endet nach der Vorbereitung Liest den gespeicherten Plan, prüft seine Identität und bereitet Dateien und Artefakte vor. Er belegt keinen Pool-Worker.
clabwire-Sidecar In jedem Geräte-Pod · bleibt aktiv Bereitet lokales Networking vor, verbindet Links und Management und meldet die Connectivity-Readiness, während das NOS läuft.
Current scaling context · 08b94a3. Startup admission can intentionally hold planning. A larger planner pool cannot shorten that wait or make devices boot faster. The default worker requests are 10m CPU / 32Mi, with limits of 1 CPU / 512Mi. Measure actual usage separately. See both admission gates and startup milestones.
Aktueller Skalierungsstand · 08b94a3. Startup-Freigaben können Planung bewusst zurückhalten. Mehr Planner verkürzen diese Wartezeit nicht und booten Geräte nicht schneller. Standard-Worker-Requests sind 10m CPU / 32Mi, Limits 1 CPU / 512Mi. Echten Verbrauch separat messen. Siehe beide Freigabe-Gates und Start-Meilensteine.
05 · Capacity

Four is the default. You can change it.

Vier sind Standard. Du kannst das ändern.

Set the pool size in the Clabernetes Helm values. Replicas control how many planning requests can execute at once, not how many devices the lab can contain.

Die Pool-Größe steht in den Clabernetes-Helm-Werten. Replicas bestimmen die gleichzeitig ausführbaren Planungsanfragen, nicht die Anzahl der Geräte im Lab.

Helm values 
plannerPool:
  enabled: true
  replicas: 4
Concurrency

When more workers help

Wann mehr Worker helfen

More workers can shorten a queue of independent planning requests if CPU, memory and registry access have spare capacity. They do not accelerate the boot of a particular NOS or the image pull for its device Pod.

Mehr Worker können eine Warteschlange unabhängiger Planungsanfragen verkürzen, wenn CPU, RAM und Registry-Zugriff freie Kapazität haben. Sie beschleunigen weder den Boot eines einzelnen NOS noch den Image-Pull seines Geräte-Pods.

Resources

Why not one worker per Node?

Warum nicht ein Worker pro Node?

Large bursts would create many helper Pods competing with the devices for scheduling, CPU and memory. A bounded pool keeps that demand predictable. With the pool enabled, the Node controller and planner-session controller each have 16 reconcile workers. Node planning and status observations share those Node workers; each pool Pod handles one request at a time. Extra replicas above 16 cannot all receive planning work at once.

Große Startwellen würden viele Helfer-Pods erzeugen, die mit den Geräten um Scheduling, CPU und RAM konkurrieren. Ein begrenzter Pool hält diesen Bedarf kontrollierbar. Mit aktiviertem Pool haben Node- und Planner-Session-Controller jeweils 16 Reconcile-Worker. Node-Planung und Status-Beobachtungen teilen die Node-Worker; jeder Pool-Pod bearbeitet eine Anfrage gleichzeitig. Über 16 Replicas können nicht alle gleichzeitig Planungsarbeit erhalten.

Fallback: plannerPool.enabled: false selects the per-request worker-Pod path. With the pool enabled, a request has a five-minute upper time bound and a 64 MiB aggregate input-payload limit. Larger input payloads need the fallback path; these bytes are planning inputs, not device image layers.
Fallback: plannerPool.enabled: false wählt den Pfad mit einem Worker-Pod pro Anfrage. Bei aktivem Pool gilt eine Zeitobergrenze von fünf Minuten und eine Grenze von 64 MiB für die gesamten Eingabedaten einer Anfrage. Größere Eingaben brauchen den Fallback-Pfad; gemeint sind Planungseingaben, keine Geräte-Image-Layer.
06 · Boundaries

Reuse without sharing a request’s state.

Wiederverwendung ohne geteilten Anfragezustand.

One at a time

A locked worker slot

Ein gesperrter Worker-Slot

A worker lock prevents overlapping planning processes in the same Pod, including during controller handover. A disconnected request can run until its local deadline; the slot is reusable after its process exits.

Eine Worker-Sperre verhindert überlappende Planungsprozesse im selben Pod, auch beim Controller-Wechsel. Eine getrennte Anfrage kann bis zu ihrem lokalen Zeitlimit weiterlaufen; nach Prozessende ist der Slot wieder verfügbar.

Clean workspace

Files belong to one request

Dateien gehören zu einer Anfrage

Each process gets private scratch space. Cleanup removes stale request files before reuse, and the worker’s parent process reaps exited children. A failed request does not become a successful cached plan.

Jeder Prozess bekommt privaten Scratch-Speicher. Vor der Wiederverwendung werden veraltete Anfragedateien entfernt; der Elternprozess räumt beendete Kindprozesse auf. Eine fehlgeschlagene Anfrage wird nicht als erfolgreicher Plan gecacht.

Limited access

The controller supplies the facts

Der Controller liefert die Fakten

Workers have no Kubernetes token or container-runtime socket and use a read-only root filesystem. The controller supplies image metadata and external file contents. A default-deny NetworkPolicy restricts worker traffic when enforced by the CNI.

Worker haben weder Kubernetes-Token noch Container-Runtime-Socket und nutzen ein read-only Root-Dateisystem. Der Controller liefert Image-Metadaten und externe Dateiinhalte. Eine Default-Deny-NetworkPolicy beschränkt den Worker-Traffic, sofern das CNI sie durchsetzt.

07 · Changes

Add a cable. Replan the affected devices.

Ein Kabel hinzufügen. Betroffene Geräte neu planen.

A new Link changes the inputs of its endpoints. The pool creates their updated plans; the device kind determines how those plans can be applied.

Ein neuer Link verändert die Eingaben seiner Endpunkte. Der Pool erstellt deren aktualisierte Pläne; das Geräte-Kind bestimmt, wie sie angewendet werden können.

Startup

Let both devices boot

Beide Geräte booten lassen

The sidecar’s /startupz gate checks local preparation. It does not wait for the remote NOS to be healthy. Its separate /readyz gate checks connectivity, avoiding a circular wait where each endpoint blocks the other’s startup.

Das /startupz-Gate des Sidecars prüft die lokale Vorbereitung. Es wartet nicht auf ein gesundes entferntes NOS. Das getrennte /readyz-Gate prüft die Konnektivität und vermeidet, dass beide Endpunkte gegenseitig ihren Start blockieren.

Disruption

The kind still matters

Das Kind bleibt entscheidend

Live-capable changes can keep the device Pod. A kind requiring Restart or Recreate gets a replacement Pod with a fresh network namespace. That can interrupt traffic through that device; a planner pool does not make every cable change hitless.

Live-fähige Änderungen können den Geräte-Pod behalten. Verlangt ein Kind Restart oder Recreate, bekommt es einen Ersatz-Pod mit frischem Netzwerk-Namespace. Das kann seinen Traffic unterbrechen; ein Planner-Pool macht nicht jede Kabeländerung unterbrechungsfrei.

The pool finishes before the cable is ready. Planning describes the desired device. Kubernetes runs it, and clabwire applies the wiring. These are separate stages with separate lifetimes.
Der Pool ist fertig, bevor das Kabel bereit ist. Planung beschreibt das gewünschte Gerät. Kubernetes betreibt es, und clabwire setzt die Verkabelung um. Das sind getrennte Phasen mit unterschiedlicher Lebensdauer.
